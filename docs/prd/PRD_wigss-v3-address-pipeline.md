## 1. Overview

### 1.1 Problem Statement

WIGSS는 화면의 요소와 소스 코드를 **className 문자열 검색**으로 잇는다.
`ab/` 하네스로 실측한 결과(2026-09-02, 1d6ea7f 기준):

- 흔한 패턴 10종에서 의도한 편집이 나온 비율 **5/10**. 그중 3건은 거절이 아니라
  **엉뚱한 편집을 씀** (저장은 성공으로 보고됨).
- 같은 className을 가진 컴포넌트가 N개면 정확도가 정확히 **1/N** (N=32에서 3%).
- 저장 1회에 소스 **40개 파일 · 162,606바이트**를 읽는다 (필요한 것은 1개 · 284바이트).
- `findTwClass`가 브레이크포인트 접두사를 무시해 **lg에서 한 편집이 base 토큰을 덮어쓴다**
  (`h-32 md:h-48 lg:h-64` → `h-80 md:h-48 lg:h-64`). 화면에 아무 신호가 없다.
- 위쪽 마진이 없으면 `pxToTw`를 거치지 않고 `mt-[12px]` **임의값을 하드코딩**한다
  (12px는 스케일에 `mt-3`으로 존재).
- `/api/rollback`이 **파일 전체를 스냅샷으로 복원**해, 저장 후 사용자가 같은 파일의
  다른 줄을 고쳤다면 그 수정이 사라진다 (데이터 손실, 재현됨).
- 스캔 응답 스크립트가 `demo-target/src/app/layout.tsx` 안에만 있어
  **임의의 사용자 프로젝트에서는 컴포넌트가 하나도 잡히지 않는다**.
- CLI `--port`가 iframe URL에 배선되어 있지 않다 (`page.tsx`에 `:3001` 하드코딩).

원인은 흩어져 있지 않다. **조인 키가 "검색된 문자열"이라는 결정 하나**에서
중복 모호성·동적 className 실패·전체 파일 I/O·apply의 재조회가 전부 내려오고,
**번역이 부모 레이아웃을 모른다는 결정**에서 사후 검증과 위험한 롤백이 내려온다.

### 1.2 핵심 발상

React의 개발 모드 JSX 변환 `jsxDEV(type, props, key, isStatic, source, self)`는
다섯 번째 인자로 **파일·줄·칸을 이미 받고 있다** (React DevTools의 "소스 열기" 근거).
이 값을 DOM 속성 `data-wigss="file:line:col"`로 꺼내면 조인은 검색이 아니라 조회가 된다.

전달 경로는 커스텀 `jsxImportSource` 하나다 — 사용자 설정은 tsconfig 한 줄,
Babel/SWC 플러그인 불필요, 프로덕션 빌드는 `jsxDEV`를 쓰지 않으므로 무영향.

### 1.3 Goals

- **G1 · 조인**: 요소 해석을 주소 기반으로 바꾼다. 파일 내·파일 간 중복과 무관하게
  스캔된 요소가 소스의 정확한 노드로 해석된다. (하네스 실험 2: A도 N과 무관하게 100%)
- **G2 · 범위 전달**: `CodeDiff`에 문자 범위를 실어 `/api/apply`가 `indexOf` 재조회 없이
  오프셋으로 치환한다. (하네스가 잡아낸 설계 결함 — 주소만 고치면 apply에서 다시 샌다)
- **G3 · 브레이크포인트**: 편집이 **현재 뷰포트를 지배하는 토큰**에 떨어진다.
  lg에서 한 편집이 base를 건드리는 사고를 없앤다. (실험 1 / S6)
- **G4 · 컨벤션**: React·Next·Tailwind 대상 경로에서 스케일에 있는 값은 프리셋으로 쓰고
  (`mt-3`, `mt-[12px]` 아님), 같은 브레이크포인트의 충돌 토큰을 정리하며,
  Tailwind 프로젝트에서는 인라인 스타일을 새로 주입하지 않는다. 못 쓰면 **사유와 함께 포기**한다.
- **G5 · 롤백 안전**: 롤백은 파일 복원이 아니라 **쓴 범위의 역치환**이다. 우리가 쓴 텍스트가
  이미 바뀌었으면 수행하지 않고 거부 사유를 돌려준다. `.bak.<ts>` 사이드카 생성을 없앤다.
- **G6 · 배선**: 스캔 런타임을 패키지가 주입 가능한 형태로 제공하고(데모 전용 탈출),
  `--port`가 iframe URL까지 배선되며, CLI 버전이 package.json에서 나온다.

### 1.4 Non-Goals (Out of Scope)

- **캔버스 편집 표면** (무한 캔버스, 반응형 세트, 드롭 판정 UI) — 목업으로 방향은 검증됨.
  별도 트랙. 이 PRD는 파이프라인과 배선만 다룬다.
- **StructureIntent** (순서/부모 변경) — 판정 UI 없이 파이프라인만 먼저 넣으면 반쪽이라 보류.
- **AI 폴백 T1/T2** — 4단계 실패 데이터가 쌓인 뒤 설계한다 (리포트 6-02의 순서 논리).
- **css-module / plain-css / html-css 리라이터 제거** — 대상 스코프는 React·Next·Tailwind로
  좁히지만, 출하된 리라이터와 252개+ 기존 테스트는 건드리지 않는다. 신규 투자만 중단.
- **검증 자동 재시도 루프** — 이번에는 타이밍의 이벤트화와 안전한 롤백까지.
  재시도는 후보 목록 반환(디스패처 API 변경)이 필요해 다음 PRD.

## 2. Phase 0 — 게이트 스파이크 (반나절)

**질문**: Next(SWC)가 tsconfig의 `jsxImportSource`를 존중해 커스텀 dev 런타임을 부르는가?

검증 방법: demo-target(Next 14)의 tsconfig에 `jsxImportSource` 설정 + 런타임 모듈 배치
→ dev 서버 기동 → DOM에 `data-wigss` 속성이 찍히는지 브라우저로 확인.

| 결과 | 다음 행동 |
|------|-----------|
| A. 동작 | 이 PRD 그대로 진행 (기본 경로) |
| B. SWC가 무시 | `.babelrc` 경로(플랜 B) 문서화 후, 파이프라인 작업은 동일하게 진행 — 주소의 **생산 수단**만 달라지고 소비 측은 같다 |
| C. 부분 동작 | 제약을 PRD에 기록하고 지원 매트릭스 명시 |

> **Phase 0 결과 (2026-09-02 기록)**: **A. 동작 확인.** Next 14.2.35(SWC, webpack dev)가
> tsconfig `jsxImportSource: "wigss"`를 존중한다. demo-target DOM 요소 152개 중 132개에
> `data-wigss="<절대경로>:<줄>:<칸>"`이 부착됐다 (미부착 20개는 head 내부 등 React 외부 노드).
> 좌표계: 줄은 1-기반, **칸도 1-기반** — Babel `loc.start.column`(0-기반) 대비 +1.
> (실측: `<nav>`가 SWC 6:5, Babel 6:4.) 리졸버는 `col-1` 우선, `col` 폴백으로 매칭한다.
> 경로는 절대경로로 오므로 서버가 SOURCE_PATH 기준으로 상대화한다.

## 3. Phases

### P1 — 주소 생산: `wigss/jsx-dev-runtime` + 스캔 런타임 (G1, G6)

- `jsx-dev-runtime.js` / `jsx-runtime.js`를 패키지 export로 추가.
  dev 런타임은 DOM 요소(`typeof type === 'string'`)에만 `data-wigss` 부착, 프로덕션 경로는 react 패스스루.
- 스캔 스크립트를 `demo-target/layout.tsx` 인라인에서 **패키지 모듈**(`wigss/scan`)로 승격.
  demo-target은 그 모듈을 import해서 지금과 동일하게 동작 (레이아웃의 인라인 스크립트 제거).
- 스캔 페이로드에 `address` 필드 추가 (`data-wigss` 값). `DetectedComponent.sourceAddress?` 신설.
- **수용 기준**: demo-target을 브라우저로 열었을 때 카드 div에 `data-wigss="src/components/Card.tsx:L:C"`가
  보이고, 스캔 결과의 각 컴포넌트에 sourceAddress가 실린다. 기존 스캔 필드는 전부 유지.

### P2 — 주소 소비: 해석·범위·apply (G1, G2)

- `src/lib/agent/address-resolver.ts`: 주소 → AST 노드 → 편집 가능한 정적 조각과 문자 범위.
  (문자열 리터럴 / 템플릿 정적부 / cn() 첫 문자열 인자 — ab/versionB의 검증된 로직을 제품화)
- `CodeDiff.range?: { start; end }` 신설. range가 있으면 `/api/apply`는 오프셋 치환
  (기존 가드 동일 적용), 없으면 기존 `indexOf` 경로 유지 (하위 호환, D6).
- `/api/refactor`: 컴포넌트에 sourceAddress가 있으면 **그 파일 하나만** 읽고 주소로 해석.
  없으면 기존 수집·검색 경로 (저하 동작).
- **수용 기준**: `pnpm test` 340 유지 + 신규 유닛. 하네스 실험 1에서 A(=출하 경로에 주소를 준 경우)가
  S1·S2·S3·S4·S9·S10 통과. 실험 2에서 A가 N과 무관하게 100%.

### P3 — 지배 토큰 편집 + 컨벤션 (G3, G4)

- `tailwind-utils`: `findTwClass`를 브레이크포인트 인식 버전으로 교체.
  지배 토큰 = 해당 속성 토큰 중 bp ≤ 활성 뷰포트에서 가장 큰 것. 교체는 그 토큰의 접두사 유지.
  없으면 base로 추가 (D3).
- 마진 추가 경로의 `mt-[${dy}px]` 하드코딩 제거 → `pxToTw` 경유 (프리셋 우선).
- 컨벤션 린터(경량): 같은 (bp, 속성) 충돌 토큰 제거. Tailwind 프로젝트
  (`tailwind.config.*` 존재)에서는 인라인 폴백 대신 **사유 있는 포기** —
  `generateRefactorResult`가 `skipped: {componentId, reason}[]`를 반환하고 API가 실어 나른다.
- 편집 요청에 `viewportWidth` 전파: 에디터 → `/api/refactor` → intent. 미전달 시 1280 가정.
- **수용 기준**: 실험 1의 S6(반응형)·S8(마진 프리셋) 통과. 파일 단위 오염 검사 0 유지.
  비-Tailwind 소스에 대한 기존 인라인 테스트는 그대로 통과.

### P4 — 안전과 배선 (G5, G6)

- 롤백: backup 엔트리를 `{path, ranges: {original, modified}[]}`로 확장하고
  역치환 + 불일치 시 `409 { reason }`. `.bak` 사이드카 생성 제거 (해당 테스트 갱신).
- `page.tsx` targetUrl 하드코딩 제거: 서버가 `TARGET_PORT`를 `/api/settings` GET에 실어주고
  에디터가 그것으로 iframe URL 구성 (쿼리 `?target=` 오버라이드 허용).
- `bin/cli.js` 버전을 package.json에서 읽기.
- **수용 기준**: 실험 3b 시나리오를 유닛으로 옮겨 통과 (동시 수정 보존 / 이중 수정 거부).
  `--port 3010`으로 띄운 데모가 실제로 iframe에 뜬다 (E2E 캡처).

### P5 — 검증 타이밍 이벤트화 (부분)

- 고정 4.5s 체인 중 **iframe 리로드 → 재스캔** 구간을 load 이벤트 + scan-result 수신 기반으로.
  (전체 재시도 루프는 Non-goal, 타이밍만)
- **수용 기준**: 데모 기준 저장→검증 체감 시간 단축을 E2E 로그로 기록.

### P6 — 회귀 확인과 기록

- `pnpm test` / `pnpm test:ab` / `tsc --noEmit` 전부 통과.
- 하네스 결과 재생성 후 **커밋** — A열 개선이 곧 이 PRD의 성적표다.
- 남는 갭(포기 사유 카탈로그, 미해결 케이스)을 이 문서 §5에 기록.

## 5. 구현 후 기록 (완료 시 갱신)

- Phase 0 결과: **GO.** Next 14.2.35 의 SWC 가 tsconfig `jsxImportSource` 를 존중한다.
  `jsxDEV` 5번째 인자(source)로 file/line/column 이 들어오고, 커스텀 런타임이
  `data-wigss="file:line:col"` 을 DOM 에 부착한다. 주의: SWC 컬럼은 1-기반
  (Babel 컬럼 + 1) — 해석기는 col-1 을 먼저 시도하고 col 로 폴백한다.
- 하네스 최종 수치 (2026-09-02 재생성, 커밋 포함):
  - 본 하네스: A **10/10** (개선 전 5/10) · 오편집 0 · 오염 0 · 평균 읽은 파일 40→1
  - 실험 2 (중복 밀도): 전 N(1~32)에서 **100%** (개선 전 1/N — N=32 에서 3%).

  - 실험 3a (저장 1회 비용): 40파일/106,476B → **1파일/284B** (375× 감소)

- 알려진 잔여 한계 (포기 사유 카탈로그):
  1. 주소 부착은 dev 전용 — 프로덕션 빌드(jsx-runtime)는 source 인자가 없다.
     프로덕션에서는 D6 저하 경로(기존 조인)로 동작
  2. RSC(서버 컴포넌트) 미검증 — 이번 스코프는 클라이언트 렌더 데모 기준
  3. 비 Tailwind 프로젝트의 스타일 편집은 인라인 폴백 대신 **사유 있는 스킵**
     (D4 — 오염 금지가 우선)
  4. spread props / 부모에서 내려온 className 은 주소 해석 실패 → 스킵. T1 후보
  5. 구조 reorder 는 같은 함수 스코프의 JSX 리터럴 형제만. `.map` 반복·함수
